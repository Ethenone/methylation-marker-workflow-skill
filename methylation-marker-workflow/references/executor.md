# Controlled local executor v2
scripts/executor.py submit <jobs_dir> <job_id> <spec.json>; status <jobs_dir> <job_id>; retry with same spec explicitly creates a new failed/timeout attempt.
Required spec: reviewed=true, review_note, absolute argv array, timeout_seconds (0..3600), code [{path,sha256}], outputs [relative filenames]. Optional inputs use the same hash schema; argv supports {work_dir}; env allows only OMP/MKL/OPENBLAS_NUM_THREADS.
Same request returns persisted state without execution; changed request/input/code or tampered passed outputs is rejected. Detached supervisor, independent attempt directories, logs, exit codes, receipts and hashes preserve failure history. Scientific QC and checkpoint advancement remain separate.
NOT a full security sandbox: reviewed is a review declaration, not enforcement. No filesystem/network/credential isolation or hard CPU/memory/GPU quotas. System/user directory environment and PATH are inherited. Timeout termination is best-effort process-tree cleanup, cannot guarantee escaped descendants. Only reviewed trusted adapters may run.
Recovery restores persisted state in a new caller; active duplicates do not launch again. Supervisor crashes, stale starting/running or submit.lock require manual process/log reconciliation. No automatic retry or PID-based cleanup for ambiguous interrupted state. PID may be reused. Preserve original records and create a separately audited new job when recovery requires intervention. This release does not automatically repair supervisor crashes or guarantee power-loss transactions.
recover <jobs_dir> <job_id> reconciles a matching terminal receipt with hashes. Missing terminal exit code is blocked; never treats a live/unknown child as retriable. Windows state replacement retries transient PermissionError. Recovery fault injection is labeled in acceptance.py.
